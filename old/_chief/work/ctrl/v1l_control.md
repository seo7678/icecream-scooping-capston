## 1. 모델 — 무엇을 제어하나

```
            합판 고정 브리지:  Z(NEMA17, TR8 리드 2, 자립, 4080 기둥) ── θ(NEMA17 + 1:27) ── 스템 ── 스쿱
                                                               │ 절삭력
   ┌──────────── 이동 베드 X (NEMA17, TR8 리드 4, 합판 데크 + SBR16) ─┼───────────┐
   │  [컵 x=471]   [팬 + 단열 홀더]  ← 수직 20 kg 단일점 셀(F_z)      ▼           │
   │                  └─ 판스프링 플렉서 + X 50 kg 단일점 셀(F_x), 위 질량 7.2 kg │
   └──────────────────────────────────────────────────────────────────────────┘
   Y 레인: 팬 홀더를 인덱스 핀 구멍(−38 / 0 / +38 mm)에 손으로 옮겨 꽂음, 구멍마다 스위치 1개
```

| 모델 | 식 | 근거 |
|---|---|---|
| 절삭력 | F_x = u·A(d), F_z = k_v·F_x (k_v = 0.5) | A02, A04. A(d)는 `calc/cartesian_model.swept_area`와 같은 식 |
| 1 portion 깊이 | 레인 270 mm에서 d = 14.7 mm, dV/V = 9.3 %/mm | `stroke_volume`, 같은 식 |
| 구조 처짐(스쿱 끝 수직) | δ_z = C_zz·F_z + C_zx·F_x | 기계 추정 ≈ 0.002 mm/N(수직 요소 + 셀). 보수 쪽 0.01–0.05 mm/N도 계산 → T3 교정으로 확정 |
| X 경로 강성 | 112 N/mm (66–149) | 기계 §13.3 H2 |
| 힘 플랫폼(X) | X 셀 힘 = F_cut + m·a_bed + 진동, m 7.2 kg, f_n ≈ 76 Hz | 결정 구성, 셀 정격 처짐 0.3 mm 가정 |
| HX711 | 80 SPS, 정착 50 ms(전자 담당 원문 확인). 필터 ≈ sinc⁴, 군지연 ≈ 25 ms | 필터 모양·군지연은 가정(확인 필요) |
| GRBL | 사다리꼴 가감속(축당 가속도 하나), 15블록 플래너, feed hold는 준비된 세그먼트(≤ ~50 ms) 소진 후 감속 | GRBL 1.1 구조 추정(확인 필요) |

제어 문제는 다섯 개다: ① 순서(상태기계) ② 표면 검출 ③ 버퍼링된 궤적에서의 깊이·힘 조절 ④ 과부하 정지 ⑤ R7 게이트. ①③⑤의 판단은 노트북이, ②④의 **시간이 급한 판단은 Nano가 하드웨어 핀으로** 한다. 그 하드웨어 핀이 살아 있는지는 **호스트와 Nano가 서로 대조**한다(§8.5).

### 2.2 추천: GRBL 1.1h on Uno + CNC Shield V3 (결정됨)

1. 위치를 유지하는 감속 정지, 노트북 없이 걸리는 레벨 감지 도어 입력, 트리거 순간 위치를 기록하는 프로브 입력이 기본 기능이다. 상태 보고의 `Pn:`으로 호스트가 입력 핀의 실제 상태를 볼 수 있어 선로 단락을 대조할 수 있다.
2. 노트북 OS를 가리지 않는다. Klipper는 리눅스 호스트가 필요하고, 보낸 동작을 감속 정지할 방법이 셧다운뿐이다.
3. 축 수가 정확히 맞다(X, Z, θ).
4. 가장 싸고 자료가 가장 많다.
5. 막히면 같은 명령 체계의 grblHAL로 옮긴다(호스트 코드 그대로).

약점: 8비트·~30 kHz, 작은 버퍼, θ 단위 혼합, 엔코더 없음(탈조를 모름 → 결함 후 항상 재원점), 컴파일 옵션 재빌드, CNC Shield V3 핀 표기 차이.

### 2.3 GRBL 설정 (초안, ASSUMPTION)

| 설정 | 값 | 이유 |
|---|---|---|
| 컴파일: `ENABLE_SAFETY_DOOR_INPUT_PIN` | 켬 | A1 = 도어(레벨 감지, 닫히기 전 재개 불가) |
| 컴파일: `INVERT_CONTROL_PIN_MASK`(도어 비트) | 켬 | 풀업(끊김·무전원) = 도어 열림 = 정지. 발판·Nano가 LOW로 끌어야 허가 |
| 컴파일: `HOMING_CYCLE_0/1/2` | Z → X → Y(θ) 각각 | Z를 먼저 올린다(R7) |
| 컴파일: `REPORT_FIELD_PIN_STATE` | 켬(기본) | 상태 보고 `Pn:` — 선로 대조 |
| `$1` | 255 | 정지 중 드라이버 유지 |
| `$3` | X 반전 | 이동 베드: G-code X = 팬 기준 공구 위치 |

## 5. 표면 검출(터치오프)

**모델.** Z0 오차 = 임계 압입 δ_th(재료, 3 N에서 0.03–0.31 mm) + 구조 처짐 C_zz·3 N(0.005–0.09 mm) + 하강 속도 × 검출 지연. 앞 두 항과 지연 평균은 고정 편향이라 제품별로 보정한다(`DELTA_BIAS`).

**선정 이유.** Nano가 F_z ≥ 3 N이면 GRBL 프로브 핀을 바꾸고 `G38.2`가 트리거 순간 위치를 준다. USB·파이썬·세그먼트 지연이 위치 기록에 들어가지 않는다.

| 2 | 프로브 핀, 80 SPS | 0.06 | 0.008 | 0.11 | 2.5 |

## 7. 이동 베드 관성과 에일리어싱 (76 Hz)

**관성.** X 셀 위 7.2 kg × 0.5 m/s² = 3.6 N. 모의(76 Hz, 추정 질량 6.2 kg): 원신호 최대 오차 3.7 N, 명령 가속도 그대로 빼기 3.6 N(HX711 지연 때문에 효과 없음), 같은 필터 통과 가속도 빼기 0.57 N, **등속 구간만 0.23 N**. → u 추정·부피·깊이 적응은 등속 구간 평균(레인 양 끝 3.3 mm 제외), 과부하 판정은 전 구간 + 3.6 N 여유.

![bed inertia](fig_v1l_bed_inertia.png)

**에일리어싱 재검토(Red Team M6).** 셀 경로 강성 1.63 N/µm, 7.2 kg → f_n ≈ 76 Hz. 80 SPS에서 |80 − 76| = **4 Hz로 접혀 대역 안에 들어온다.** 그러나:

| 진동 f [Hz] | 접힌 f [Hz] | sinc¹(최소, 변환 주기 적분만) 이득 | 1 N 지속 진동의 20 mm 구간 평균 잔차 sinc¹ / sinc⁴ |
|---|---|---|---|
| 53 (셀·플렉서 무름) | 27 | 0.42 | 0.000 / 0.000 N |
| 70 | 10 | 0.14 | 0.006 / 0.000 N |
| **76** | **4** | **0.052** | **0.005 / 0.000 N** |
| 79.5 | 0.5 | 0.006 | 0.005 / 0.000 N |
| 108 (단단) | 28 | 0.21 | 0.003 / 0.000 N |

- 0 Hz 근처로 접히는 진동은 곧 80 Hz 근처이고, 변환 주기로 적분하는 ADC(델타-시그마)는 그곳에 **영점**이 있다. 구간 평균이 못 지우는 저주파 쪽은 필터가 지운다. 최대 잔차는 sinc¹ 가정에서도 0.007 N.
- 과도 진동(가속 때)은 ζ 0.05·τ ≈ 42 ms로 등속 구간 전에 줄어든다.
- **판단: 80 SPS 유지.** 10 SPS로 내려도 76 Hz는 같은 4 Hz로 접히고(10의 배수 80), 지연만 260 ms 늘어난다. 위험은 HX711 필터 길이가 출력 주기와 다를 때뿐이다 → **T6**: 빈 팬·찬 팬 등속 이동 중 0.5–5 Hz 맥놀이 확인. 보이면 플렉서 강성·질량으로 f_n을 옮기거나 고무 감쇠를 넣는다.

## 8. 안전과 워치독 (R7 포함)

> 식별한 위험과 대책, 측정할 값을 적는다. 장치가 안전하다고 주장하지 않는다. 시험 중 작업자 입회, 가드, hold-to-run은 V1-S와 같다.

### 8.1 계층

| 계층 | 무엇으로 | 막는 것 | 노트북이 멈추면 |
|---|---|---|---|
| 하드웨어 | E-stop → K1 모터 전원 차단 + GRBL 리셋. 발판 → 허가선. 기계식 과부하 스톱 | 사람 개입, 셀 과부하 | 그대로 |
| Nano (독립 MCU) | 허가 트랜지스터 = 무장 ∧ 래치 없음 ∧ 하트비트 ∧ 레인 1개 ∧ K1 ON ∧ (Z-높이 ∨ X-창). F ≥ 120 N 래치. 프로브 출력. **선로 되읽기** | 과부하, 노트북 정지, R7 위반, 레인 핀, 선로 단락 | 그대로(단락 래치는 표시만 — 멈추는 것은 호스트) |
| GRBL | 소프트·하드 리밋, Z 먼저 원점, `$110` 60 mm/s, 도어 레벨 감지 | 행정 밖, 게이트 우회 속도 | 버퍼 블록까지 실행 |
| 호스트 | `request_xy_move()` 게이트, 상태별 힘 한계, 통신 감시, **Pn 대조·자가시험**, 로그 | R7, 순서 오류, 과부하(먼저), 선로 단락 | 없음 |

### 8.2 R7 — Z < Z_SAFE이면 수평 이동 금지

- **호스트:** 모든 수평 이동은 `request_xy_move()`를 지난다. TRAVEL은 계획 Z와 측정 Z가 모두 **Z_SAFE + 2 = 62 mm 이상**일 때만(L2). 이송 높이는 70 mm. 예외는 DIVE/DRAG 상태에서 현재·목표가 팬 레인 작업공간 안인 SCOOP뿐(`firmware/state_machine.md` §3.1의 드래그 예외; PROJECT.md R7 명시는 성원님 확인 필요 — Red Team L3). 거부하면 `EV_XY_BLOCKED_LOW_Z`.
- **Nano 인터록(하드웨어):** Z-높이 스위치(**Z ≥ 60.5 mm에서 ON**, 반복성 ±0.3 mm 가정 → 켜져 있으면 항상 Z_SAFE 이상) 또는 X-창 스위치 중 하나라도 켜져 있어야 허가. 둘 다 꺼지면 도어 hold + 래치. 조정: 스위치를 Z_SAFE + 0.5 mm에서 켜지게 맞추고 10회 반복성을 잰다(T4).
- **GRBL:** `$110` 60 mm/s(우회 시 창 밖 6.7 mm < 벽 여유 8 mm), 소프트 리밋, Z 먼저 원점.
- **Y(수동 인덱스, M10 통일 절차):**
  1. Z를 이송 높이 70 mm로 올린다(스쿱을 팬 밖으로), 허가 해제(E0).
  2. 작업자가 **E-stop**을 누른다 → K1이 모터 전원을 끊는다. 호스트는 Nano의 K1 보조 접점 입력으로 확인할 때까지 기다린다.
  3. 핀을 옮긴다. **레인 스위치 3개 중 정확히 1개가 켜지고 그것이 요청 레인**이어야 한다(아니면 `LANE_MISMATCH`).
  4. E-stop 해제 → "모터 ON".
  5. **재원점**(모터 무전원 동안 베드를 밀었을 수 있다; Z 먼저) → **선로 자가시험**.
  레인이 이미 맞으면 1–5를 건너뛰고 자가시험만 한다.
- **복구:** Z가 낮은 채 창 밖에 멈추면 인터록이 모든 축을 막는다. 발판을 밟은 채 `U`(1회 우회)로 Z만 올린다. Z-높이 스위치가 켜지면 자동 해제.

### 8.3 게이트 우회 시 정지 여유 (창 끝 = 레인 끝 + 2 mm, 벽 여유 10 mm)

| 이송 속도 | 창 밖 추가 이동(nom / worst) | 벽까지 남는 여유 |
|---|---|---|
| 40 mm/s | 3.2 / 3.6 mm | 4.8 / 4.4 mm |
| **60 mm/s** | **6.1 / 6.7 mm** | **1.9 / 1.3 mm** |
| 80 mm/s | 9.7 / 10.5 mm | 벽 접촉 |

여유가 1–2 mm로 작다 → T4에서 재고, 부족하면 40 mm/s로 낮추거나 창을 좁힌다. 이동 홀더와 뒷벽·창 하단 사이 끼임(Red Team M5)은 기계 쪽 조치이며, 60 mm/s 상한은 그대로 둔다.

### 8.5 선로 단락 검출 (Red Team M4)

허가선(A1)이 발판 케이블(바닥)이나 케이블 체인에서 GND에 닿으면 발판·Nano 120 N 정지·워치독·R7 인터록·레인 핀이 한꺼번에 GRBL에 닿지 않는다. 프로브선(A5) 단락이면 `G38.2`가 접촉을 못 본다. 세 겹으로 감시한다.

| 층 | 방법 | 판정 | 반응 |
|---|---|---|---|
| ① Nano 되읽기 | A6·A7로 A1·A5 전압을 매 샘플(80 SPS) 읽는다 | 허가 트랜지스터 OFF **또는** 발판 뗌인데 A1이 LOW, 프로브 트랜지스터 OFF인데 A5가 LOW → 2샘플(25 ms) 연속이면 `FL_LINE_FAULT` 래치 | 호스트가 래치를 보고 결함 |
| ② 호스트 Pn 대조 | 새 GRBL 상태 보고마다 `Pn:D`(도어 열림)·`Pn:P`(프로브 트리거)를 Nano 플래그에서 계산한 기대와 비교. 기대 = A1 열림 ⇔ ¬(허가 트랜지스터 ∧ 발판), A5 트리거 ⇔ ¬프로브 트랜지스터 | 기대가 바뀐 뒤 60 ms 지나서, 연속 2회 불일치 | 기대 열림·관측 닫힘 = **단락** → `LINE_A1_SHORT`/`LINE_A5_SHORT`. 반대 = 단선 → `LINE_*_OPEN` |
| ③ 사이클 전 자가시험 | 정지 상태에서 E0·P0 → Pn에 D·P가 보이는지, P1 → P가 사라지는지, E1 → D가 사라지는지 | 0.5 s 안에 안 보이면 결함 | 원점 직후, 인덱스 뒤, 매 사이클 시작 |

**단락 결함 처리:** `!`(소프트웨어로 먼저 멈춤) → 정지 확인 → 0x18(큐 비움) → **E-stop 요구**(K1 차단을 확인할 때까지 대기) → 수리(발판 케이블 보호관, 체인 점검) → E-stop 해제 → 래치 해제(`R`) → 재원점 → 자가시험 통과 → IDLE. 자가시험을 통과하기 전에는 움직이지 않는다.

**한계:** 운전 중(허가 ON·발판 눌림)에 생긴 단락은 기대와 관측이 둘 다 '닫힘'이라 **그 순간에는 보이지 않는다.** 기대가 '열림'이 되는 순간(발판 뗌, Nano 정지, 사이클 끝 자가시험)에 드러난다. 그 창은 최대 한 사이클이고, 그동안 남는 보호는 호스트 '!'(105 N)·호스트 R7 게이트·통신 감시다.

| 단락 뒤 발판을 뗐을 때 | 지연 nom / worst | 30 mm/s 추가 이동 worst |
|---|---|---|
| 정상(단락 없음): 발판 접점 → GRBL 도어 | 41 / 51 ms | 2.4 mm |
| ① 되읽기 → 호스트 '!' | 76 / 153 ms | 5.5 mm |
| ② Pn 대조만(되읽기 없음) → '!' | 186 / 275 ms | 9.2 mm |

선택 보강(미구현): Nano가 단락을 보면 GRBL 리셋 핀(A0, E-stop 보조 접점과 병렬 NPN)을 당겨 즉시 정지(위치 상실 → 재원점). A0선이 단락되면 GRBL이 리셋에 머물러 움직이지 않는 쪽이다.
