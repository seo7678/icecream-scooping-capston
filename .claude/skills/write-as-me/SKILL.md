# write-as-me

인자: `<분야> <형태> <주제 또는 소재>`. 예: `capstone report 로드셀 노이즈 실험 결과`

## 순서

1. **프로파일 찾기.** `profiles/<분야>_<형태>.md` 와 `.stats.json` 을 읽는다.
   - 없으면 쓰지 말고 멈춘다. 코퍼스가 있으면 `python3 pipeline/mv.py profile <분야> <형태>` 를 먼저 돌리고, 없으면 `style-interview` 스킬로 넘긴다.
   - `.md` 의 규칙·예문 칸이 비어 있으면 "프로파일이 덜 채워졌다"고 말하고 `slop-diagnose` 를 권한다.
2. **소재 확인.** 주제만 있고 구체적 재료(숫자, 날짜, 겪은 일, 고유명사, 실패한 것)가 없으면 **지어내지 말고 사용자에게 먼저 묻는다.** 질문은 3개 이내로, 답이 짧게 나오게. 구체성이 없는 것이 AI 티의 가장 큰 원인이다.
3. **예문 읽기.** `corpus/<분야>/<형태>/` 에서 주제와 가까운 글 2~3편을 직접 읽는다 (프로파일에 적힌 대표 예문만 믿지 않는다). 그 글의 호흡, 문장 길이, 어디서 끊는지를 본다.
4. **초안 작성.** 프로파일의 규칙을 따른다. 그리고 항상:
   - `slop/patterns_ko.md` 에 있는 패턴을 쓰지 않는다. 서두 인사, 요약 결말, 균등한 불릿, 굵은 글씨 남발, 3개씩 나열, "A가 아니라 B" 반복.
   - 소재에 없는 사실을 만들지 않는다. 모르는 칸은 `[확인 필요: ...]` 로 남긴다.
   - 매끈하게 다듬지 않는다. 프로파일이 문장 길이 편차, 반복, 어색한 끊김을 보이면 그대로 둔다.
   - 길이는 프로파일의 평균에 맞춘다. 내 글이 짧으면 짧게.
5. **자체 검사** (초안을 `/tmp` 가 아니라 스크래치 파일에 저장한 뒤):
   ```
   python3 pipeline/mv.py slop <초안>
   python3 pipeline/mv.py compare <분야> <형태> <초안>
   ```
   슬롭 적중이 있거나 compare 가 4개 이상 벗어났다고 하면, 걸린 부분만 고쳐서 다시 돌린다. 최대 3회.
6. **출력.** 초안 본문, 그리고 아래를 짧게:
   - 지어내지 않고 비워 둔 곳 (`[확인 필요]`)
   - 프로파일과 여전히 어긋나는 지표가 있으면 어떤 건지
7. **피드백 요청.** "고친 최종본을 주면 기록해서 프로파일에 반영한다"고 안내한다. 최종본을 받으면:
   ```
   python3 pipeline/mv.py feedback add <분야> <형태> --draft <초안> --final <최종본>
   ```

## 하지 말 것
- 프로파일이 없는데 감으로 "그럴듯한 내 말투"를 만들어 쓰기
- 사용자가 안 준 경험담, 수치, 인용 지어내기
- 초안 끝에 요약, 인사, 추가 도움 제안 붙이기
- 검사 결과를 숨기고 통과한 척하기
